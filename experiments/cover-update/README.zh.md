# 改封面事务的离线实现

[English](README.md) · 中文

这是 #736 的草稿代码，没有浏览器或 HTTP 平台驱动，不加入 `install.sh`，也不提供
`site */cover-update` 命令。它无法修改真实作品。测试只使用合成 ID 和状态快照。

`createPlan(snapshot, files)` 把作品字符串 ID、平台、已保存封面指纹、版本、已知
修改限制、图片 SHA-256 和裁剪比例绑定到一个待确认计划。执行前先返回可能重新审核、
视频号可能只允许修改一次等限制。修改次数未知时，视频号更新会被阻止。计划哈希只用于
检查内容一致性，不是鉴权凭证。

`applyPlan` 要求传回已审核的计划 ID，并由后续平台驱动提供：

- `inspect(id)`：读取已保存的作品身份、版本、封面指纹和修改限制，不能把编辑器中
  尚未保存的预览当作已保存状态。
- `prepare(files, baseline)`：重新计算本地文件实际哈希，上传并核对每个比例，返回
  将要保存的封面指纹和文件指纹；此阶段不能保存作品。
- `commit(receipt)`：只提交一次，不在内部重试。

还必须提供持久化事务记录。`claim({platform,id,planId})` 要跨进程、跨计划原子占用
同一作品；`record(receipt)` 要在提交前写入预期封面指纹。结果不明时保留占用，直到
只读核对结果并由操作者明确处理。测试使用的内存记录只适用于模拟，尚无生产记录器或
实站驱动。

上传后、提交前会重新读取身份、已保存状态和限制，发现变化即拒绝提交。提交响应丢失
后只读一次；只有已保存封面与预期相符，才报告已验证更新。其他情况返回
`action_outcome_unknown`、`retryable: false` 和回执。后续 `reconcile` 只核对，
不再次写入。

运行 `node --test experiments/cover-update/transaction.test.js`。接入真实平台仍需
已有作品编辑页、限制提示、保存成功和失败状态的脱敏样本，以及保存后的只读核验证据。
新建投稿页样本不足以证明已有作品编辑流程可用。本草稿开发与测试没有修改已有作品。
